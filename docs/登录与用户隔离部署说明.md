# 登录与用户隔离部署说明

本版本在原有稽核平台上增加账号登录和用户隔离。材料解析、字段提取、稽核规则、模型说明和离线报告生成沿用现有实现。仍全局同时执行一个任务，SQLite 和文件存储继续使用。

## 安装与首次启用

停止旧服务并备份整个 output 目录，再替换代码与 frontend/dist。升级前等待活动任务结束。本版依赖新增 argon2-cffi，必须更新 Python 依赖；发布包已包含构建好的前端。

```bash
python -m pip install -r requirements.txt
python -m platform_app.manage_users create admin --admin
python -m platform_app.manage_users create user_a
# 发布包默认前端路径为 /chuilei/jihe/
export AUDIT_URL_PREFIX=/chuilei/jihe
# 仅在本机 HTTP 试用时设置；HTTPS 部署保持 true
export AUDIT_COOKIE_SECURE=false
python app.py
```

密码交互输入，至少12个字符，不提供默认密码。请在服务使用的同一运行环境、同一 output 挂载和相同 AUDIT_PLATFORM_OUTPUT 配置下执行账号命令。管理员仅增加账号维护和全局模型配置权限，不默认拥有其他账号的材料访问权。

macOS 双击启动脚本已保留本机 HTTP 的 Cookie 兼容设置。直接通过本机 HTTP 开发时，在启动前设置 AUDIT_COOKIE_SECURE=false；服务器 HTTPS 部署保持默认 true。

## Docker 部署

```bash
docker compose build
docker compose run --rm audit python -m platform_app.manage_users create admin --admin
docker compose run --rm audit python -m platform_app.manage_users create user_a
docker compose up -d
```

在已有 HTTPS 反向代理后部署。将 AUDIT_PUBLIC_ORIGIN 设置为用户访问的公开源，例如 https://audit.example.com，不带路径。将 AUDIT_URL_PREFIX 设置为现有代理子路径，例如 /chuilei/jihe，与前端构建时的 VITE_BASE_PATH 保持一致；根路径部署两者使用空前缀与 /。会话 Cookie 路径自动匹配前缀。

如仅在受控本机环境通过 http://127.0.0.1:8765 试用，显式设置 AUDIT_COOKIE_SECURE=false。设置仅适用于本机 HTTP；服务器通过 HTTPS 访问时应使用 Secure Cookie。

默认会话有效期8小时，可通过 AUDIT_SESSION_SECONDS 调整。普通接口每次检查会话，实时事件每轮检查，页面定期检查账号状态。退出、密码重置和账号禁用会撤销会话。保持单 API 进程部署，沿用原有进程探活与任务取消方式；本轮未改造分布式任务调度。

## 账号维护

```bash
python -m platform_app.manage_users list
python -m platform_app.manage_users reset-password user_a
python -m platform_app.manage_users disable user_a
python -m platform_app.manage_users enable user_a
```

普通用户不能修改或测试全局模型配置，仍使用管理员配置的模型。没有公开注册和找回密码页面。连续登录尝试触发15分钟限制。

## 材料与结果归属

- 上传材料：output/上传/<内部用户ID>/<材料文件夹>/。
- 新结果：output/单系统/users/<内部用户ID>/<系统标识>/。
- 数据库：output/单系统/.state/platform.db，新增 users、sessions 和 login_attempts 表，并为 systems、jobs 增加 owner_user_id。
- 普通用户只能浏览与稽核自己上传根目录中的材料；服务端原生文件夹选择入口关闭，浏览器文件夹上传继续可用。
- 历史结果文件保持原位置，首次创建的管理员接收历史系统与任务记录。历史原件不在用户目录时可查看已有结果，重新执行需重新上传材料。
- 旧数据库首次升级前自动生成 platform.db.pre-auth.bak；升级前的整个 output 备份仍是完整回退依据。新旧数据库结构不同，回退代码时需同时恢复升级前数据，先保留升级后的数据副本。

备份必须同时覆盖数据库和文件。SQLite 会话表保存会话令牌哈希，原始令牌仅通过 HttpOnly Cookie 传递。密码使用 Argon2id 哈希，账号命令不接收命令行明文密码。

## 验证

```bash
python -m unittest tests.test_auth_isolation -q
python -m unittest discover -s tests -q
cd frontend
npm ci
npm run build
npx playwright install chromium
npm run test:e2e
```

前端测试通过身份接口的测试桩覆盖登录、退出、会话过期、账号切换和现有看板；后端测试使用真实 SQLite 和 HTTP 测试客户端验证隔离。浏览器测试不调用真实模型。真实原件稽核准确率仍需在部署环境结合实际材料验证。

已安装 Google Chrome 时，测试也可设置 PLAYWRIGHT_CHANNEL=chrome 使用现有浏览器。Windows PowerShell 设置环境变量的示例：`$env:AUDIT_URL_PREFIX="/chuilei/jihe"`、`$env:AUDIT_COOKIE_SECURE="false"`。
